These are pattern-based rules for your firewall or proxy server. Wildcard domains use dynamic subdomains that cannot be tested directly. Share this list with your IT/security team.
📡 Subscription-Based Routing

Enterprise admins can use firewall rules to selectively allow or block Copilot by subscription plan. This works by routing traffic through plan-specific subdomains:

  • *.individual.githubcopilot.com — Free / Pro / Pro+ / Max (Student mapping is not documented)
  • *.business.githubcopilot.com — Business plan users
  • *.enterprise.githubcopilot.com — Enterprise plan users

Important: Do NOT add *.githubcopilot.com to your allowlist when using routing — it bypasses all plan restrictions. Below, Allow ✅ = your selected plan, Block 🚫 = unselected subscription groups.

Proxy path comparison

This separate script reads configuration clues and tests the same endpoints using curl. It does not change system, IDE, or VPN settings, execute PAC files, or sign in to Copilot. It uses the Proxy URL above, but not the basic script checkboxes.

Paths to compare
  1. Current curl configuration: uses proxy environment variables, not OS proxy or PAC settings. It may differ from the IDE's route and is not necessarily a direct connection.
  2. IT-designated proxy: uses the Proxy URL above and disables NO_PROXY bypass for this request only. Authentication is not attempted automatically.
  3. Direct: explicitly bypasses application proxies, but cannot bypass or disable VPNs, transparent proxies, or corporate network controls.

No designated proxy URL entered. Only the environment-default path is generated; this is not a proxy comparison.

How to interpret results
  • Default fails + designated proxy gets the expected health response: compare Copilot's explicit proxy settings. This does not prove PAC caused the failure.
  • CONNECT/HTTP 407: ask IT about proxy authentication. TLS errors: check the approved corporate CA and client trust store. Do not disable certificate verification.
  • HTTP 200 on a health probe checks only that request. A CONNECT 200 alone is not an endpoint HTTP 200. Login, policy, response content, and other features remain unverified.

Run and share

Run inside the environment where the client fails. For a VM, WSL, container, or remote session, select its OS, not the host OS. Follow your organization's execution policy.

.\copilot-path-check.ps1

Saves a report with a unique filename, copilot-path-check-*.json, in the current directory and prints a summary. Stages that could not be observed are marked unknown. After saving the report, the script exits with code 1 for failed or unrun checks, or code 2 for warnings or incomplete configuration collection.

The downloaded script contains your entered proxy and tenant addresses: keep it local. The JSON omits proxy/PAC URLs, credentials, response bodies, raw errors, and private tenant/enterprise identifiers. Review the JSON before sharing; no report is uploaded by this page.

After an approved configuration change, restart the affected client and retry the originally failing login or Chat operation. Collect IDE diagnostics if it still fails. This script cannot certify Copilot recovery or diagnose VPN split tunneling.
